## 確認した原因
- 通知自動入口はAPI ReaderでなくDOMを上から順にスクロール保存。閉じると進捗を破棄。
- API差分経路も新しい順に送っていた。ページ番号再開は新着でずれる。
- 表示がアイコン補完をawait。カテゴリキャッシュは最近100件に偏り切替で空白化。
- Feedは最大約1.7万行を1.2秒キャッシュで再走査。再分類は100件ずつ逐次更新し完了するまで全履歴を再訪。
- 添付の件数＋期限カードは通知ではないDOMの誤取得。DBで一致確認。原文を残しcapture_noiseに分離する。
- DM本番本文0件。2人を処理し3人進むバグと、失敗結果を成功扱いするバグ。
- 親画面のモードと内部DM選択が別状態で、別項目に移ってもDMが残る。

## 採用仕様
1. 通知画面は自動スクロール禁止。APIから取得可能範囲最大300件。取得中の一覧と次ページ要求をアカウント別journalへ保持し、収集後は古い順に20件ずつ保存。保存完了応答の署名だけ境界更新。停止・離脱時は未送信journalを残す。次回はjournalを先に処理し、その後は保存済み通知署名までの差分のみ。
2. 通知取得、表示、分類、DM、グラフは独立。カテゴリ切替は保存済みデータを即表示。本文表示はアイコン通信を待たない。保存イベント＋2秒補助確認で更新。
3. 再分類は未処理または新規未分類のみ。カーソル保存、重複カーソル停止、停止操作、分類不能はその他を維持。同じclassifierで無限再試行しない。未対応kindをアカウント別の未読/既読更新案内にする。
4. DMは相手一覧と本文完了を分ける。本文0やタイムアウトを完了扱いしない。全相手を飛ばさず巡回し、確認済みメッセージ・ルームを保存して続行。実DMの取得成功確認は別途必要。
5. 設定・詳細は明確な押せる行。お気に入り解除は各人物に表示。削除はお気に入り指定のみで本人の履歴は残す。
6. グラフは指標名・単位・期間・出典を表示。日付の実間隔で描画、欠損と0を区別、折線に架空補間しない。立体感は陰影・光沢で付け、数値の長さ/角度/比率は歪めない。
