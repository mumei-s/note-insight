## 修正

- 本体の更新案内を「通常データ」から独立させる。通常データは公開データの再取得だけを担当し、上向き矢印を除去。本体の版確認や画面取得に失敗した場合は、最新版・更新成功として扱わない。12秒の通信上限を設定し、別アカウントへ切り替えた後の応答を反映しない。
- 表記は `note公式🔔パネル ON` / `note公式🔔パネル OFF`。現行のControls/Readerが設定を参照せず、旧Runtimeだけが参照していたことが原因。設定Bridgeをnote公式でも読み込み、共有ストレージ変更通知・フォーカス復帰・定期確認で既存タブへ反映する。Bridgeを最初に読み込み、状態確認前のパネル表示を防ぐ。
- OFFはINSIGHTの追加パネル・保存位置表示を隠し、通知Readerを停止。進行中の保存確認と再開位置は既存の停止処理に従って保持する。フィルターで隠した通知も戻す。note自身の🔔・通知本文は消さない。ONで既存のパネル読取りを再開する。
- 全通知がフィルター対象になったときも、フィルター解除用の操作パネルを保持する。INSIGHTが非表示にした通知だけをパネルの存在確認に使用し、公式側が閉じた通知パネルは対象にしない。
- Dashboardは通常の折りたたみdetails、ARIA展開ボタン、指標の見出しを持つ「詳細を見る」等を展開し、遅いJSON通信や読込表示が落ち着いてから保存する。メニュー、期間タブ、購入、送信ボタンは展開対象にしない。閉じた表や非表示行は読まない。
- 複数の公式JSONを保持し、期間・URLが異なる取得結果を混ぜない。期間変更後に古いPerformance履歴のURLを再取得しない。遅れて開いたパネルの新しい値は自動保存し、同一内容の二重保存を抑える。公式合計が数値→ラベルの順でも取得する。
- 日別PVが取れていなければ「日別PV 0日（未取得）」と表示する。同期完了やINSIGHTへの自動復帰を行わない。失効した連携は日本語で説明し、「連携を直して再読込」から正しいアカウントの設定画面へ移動できる。

本番集計ではDashboardの最終保存は2026-09-09、日別データは0日。ss_yrのDashboard連携25件はいずれも失効し、有効なものは0件だった。秘密のトークン値は取得していない。

稼働中 `insight-notification-import-token` v9の実ソースとローカルが一致することを確認。通知の再連携で、同じmember_idの全用途の取込トークンを失効させていた。通知の連携済み判定も用途を区別していなかった。通知用ペアコードの再発行・交換にも同じ用途分離の欠落があった。

通知取込トークンは `note_notification_auto_sync`、ペアコードは `notification` に処理対象を限定。Dashboard・DM・別会員の連携と待機コードを維持する。Supabase関数v10を配備し、配備後ソースの完全一致を確認済み。独自ログイン認証を維持。既に失効したトークンを再有効化していない。Dashboardの「公式ダッシュボードを読み込む」操作で新しい連携を発行する。
