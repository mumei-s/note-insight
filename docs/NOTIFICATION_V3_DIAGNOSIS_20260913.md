# 本人通知V3と分析の診断・修正（2026-09-13）

最新main edc7778 のV3ローダー・復旧処理を維持して統合。前チャット側の未公開2.9.68を入口として復活させない。

## 修正

- noteのクリックイベントが途中で伝播停止されても、captureでベル操作を検出する。既存通知DOMのhidden/class/style変更でも再判定する。
- 背景のmainやbodyを通知シェルとして選ばない。通知タブ、通知専用コンテナ、ダイアログに限定。閉じた後はパネルを隠す。
- 4ボタンを等幅・中央揃えへ変更し、固定最小幅の合計がスマホ幅を超える原因を除去。
- V3ローダー3.0.1はDOM準備後に本体を読み、取得失敗時は再接続案内を出す。旧版の更新確認横取りを防ぎ、本体取得後に実版を返す。
- 既存V3が参照するautoscan-v2970のURLへ強化した読取処理を配置。古い通知が追加描画される間は通知内の下端へ進み、その後下から上へ読み取る。背景ページをスクロールしない。
- 未知文言も保存対象にし、通知ID・日時・本文・対象URLを重複判定に使用。別の記事が同じマガジンへ追加された通知をまとめない。
- 保存済み扱いはサーバーが確認した署名のみ。途中送信の確認結果を都度保存し、未保存は次回再試行。
- 返信、自記事マガジン追加、メンシプ参加を記事タイトル内の語句より優先して分類。DB後段トリガーによる誤上書きも防止。
- 通知タブは本人通知固有項目を表示。公開スキ・フォロー・通常コメントは既存の公開データ側を使用。未分類のその他は残す。
- 全履歴をページ取得してカテゴリ件数を集計。再分類はカーソル継続し、分類済みを含む全履歴を対象。誤取得ノイズの隔離を保持。
- 古い取得結果によるカテゴリ・アカウントの表示上書きを中断とリクエスト番号で防止。
- 自記事追加の対象記事・マガジンURLを保存できる場合は別々に表示。マガジン運営者を実際の追加者と断定しない。

## 分析

- 本人通知の項目別円グラフ、全期間/7/30/90日、曜日、時間帯、人物別、14日推移。
- 自記事マガジン追加、メンシプ参加、複数回反応者の件数。
- 選択期間が7日のときも前7日の比較母集団を失わない。0件の期間から全期間へ戻れる。
- 通知なしの公開分析にスキ/コメント構成比円グラフと記事反応分布を追加。既存の投稿頻度・集中度・時間・語句・記事年齢分析を維持。
- 日時未取得は保存日時、相対日時は概算として扱う。分類済み率を正答率と表記しない。

## 検証と範囲

- TypeScript + production build。
- CIの従来回帰試験に通知分類・重複・分析期間比較・DOMイベント/読取試験を追加。
- DOM試験：ベル伝播停止、背景除外、閉じる操作、未知文言保持、rootリンク保持、下から上の送信順、未確認保存の再試行。
- 保存側4関数とDB分類トリガーを更新。独自セッション/取込トークン認証を維持。
- ブラウザでは公開の導入/更新画面と戻り先を確認する。ローカル検証URLはCloud Browserの接続制限があり、実ブラウザによるローカル通知フィクスチャ試験は未実施。
- Android Edge/Firefox、iOS Safari Userscripts、PCの導入案内を掲載。各実機への拡張機能インストール、ログイン済み本人のnote通知との全件一致はこの環境では未確認。DOM試験を実機試験と呼ばない。
- note側で消えた通知、DOMへ提供されない本文/追加者/日時の復元は保証しない。
