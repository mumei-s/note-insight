## 確定する表示
画面下部のスマホ幅に収まる1パネル・横並び4列。
左から「手動読み込み」「フィルター（ON/OFF）」「設定」「INSIGHT」。
読み込み中は第1ボタンを停止操作へ切り替える。停止時はそこまでの保存結果を表示。
常駐の別ランチャーや多重パネルを増やさない。記録線は通知本文を隠さず、再表示時に復元。
可視のDashboard表記はすべて「ダッシュボード」へ変更。URL、API名、既存保存キーは互換性を維持。

## 読み込み・保存
- 本物のnote通知画面を開くと自動開始。背景の記事リストは読み込まない。
- 初回は取得できる全通知を古い側（下）から新しい側（上）へ読む。
- 2回目以降は保存境界を利用して未保存の追加分だけ取得・保存。毎回全履歴を走査しない。
- 手動読み込みは停止後の再開・再試行にも使う。未送信キューの再送を先に行う。
- 読み取った行はアカウント別の永続キューへ先に記録し、小分けでサーバー保存。
- サーバーの確認済み署名だけを保存済みにし、確認済み境界と未送信の境界を混同しない。
- 停止、通知画面を閉じる、タブを非表示にする、ページ移動のどの場合も進捗・記録線・未送信キューを保持。
- ページ終了時の通信完了はブラウザが保証しないため、保存キューを通常動作中から永続化し、次回自動再送する。未送信分を「INSIGHT反映済み」と表示しない。
- 通知IDを優先して重複排除。相対日時の変化で同一通知が増殖しない方式にする。識別情報不足を無理に同一通知と断定しない。
- noteアカウント切替時には処理を停止し、別アカウントの保存キューを送らない。
- フィルターON/OFFは表示制御。重要通知の取得・保存を消す条件にしない。

## 必須で保持する本人通知
自分の記事のマガジン追加（お返し確認に重要）、自分のコメントへの返信、コメントへのスキ、
メンシプ参加、掲示板投稿・返信・反応、購入・チップ・高評価・引用等。
未知文言も「その他」に保存し、後から再分類できる。
取得できる記事・マガジン・人物URLと日時を残す。マガジン運営者を実際の追加者と断定しない。
公開データで取るスキ・フォロー・通常コメントは既存の公開側へ分離する。

- 本人通知＋ダッシュボード同期を単一Userscriptとして配布する。案内画面だけを統合して2本を入れさせない。
- 必要な権限、note/INSIGHT対象URL、トークン保存・連携・更新確認を単一パッケージで扱う。
- 既存の通知/ダッシュボードスクリプトとの二重起動・競合を検出・抑止する。
- 本人通知不要の公開データ分析は、インストールなしで独立して使える状態を保持。
- 導入導線は「端末判定 → 必要な拡張を案内 → 統合ツール1本を導入 → 実動作と本人連携を確認 → INSIGHTメインへ戻る」。
- 文字列の画面が出ても既存導入が動いていれば、戻って実版確認へ進む。未導入を成功扱いせず、手動導入の説明は必要時だけ。
- Android Edge/Firefox、PC、iOS/Mac Safariを実際の対応可否に沿って案内。非対応ブラウザに動かない導入ボタンを出さない。
- 円グラフ、期間/人物/曜日/時間帯/記事反応分析は維持する。
