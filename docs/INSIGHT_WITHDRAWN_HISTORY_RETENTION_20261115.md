# INSIGHT 退会者・削除済み交流の保存方針（2026-11-15）

対象：`mumei-s/note-insight`。本変更では **INSIGHT利用権限の停止** と **過去の交流記録の破棄** を分離する。note退会・コメント削除・INSIGHT退会の混同を避ける。

## 確認済みの現状

- `insight_access_applications` の `status='revoked'` では本人ログインを拒否し、既存セッションを失効させる。
- 退会しても `insight_notification_profiles` は残り、`public_watch_enabled=false` になる。再参加時に同じ申請UUIDを使用する。
- 調査時点の失効申請4件すべてに保存用プロフィールがあり、通知12,654件、コメント7,248件、スキ30,227件、交流イベント2,703件が残っていた。件数は所有スコープ単位の集計であり、本人が発した反応だけを表すわけではない。
- `owner-remove` だけは公開参加者レコードを物理削除していた。変更後は `publicParticipantUpsert(next,false)` を共用し、`active=false` にする。公開APIは `active=true` だけを返すため、退会者は参加者一覧に出ない。
- 旧データでは失効申請4件中1件の公開参加者レコードが存在しない。ただし申請本体と保存プロフィールがあるため、アクセスUUIDを元に非公開の識別情報を復元する余地がある。**本パッチで既存の欠落レコードは自動修復しない。**

## 保持・アクセス制御

1. 退会時は新規ログイン・収集権限を停止し、過去の通知・スキ・コメント・DM・フォロー変動等の保存済み履歴を削除しない。
2. 退会者の公開参加者レコードは `active=false` にする。通常の一覧からは除外し、管理履歴との結合キーを保存する。
3. 再承認・再参加時も同一申請UUID/履歴を再利用する。ただし失効中の閲覧権限を与えない。
4. note側でプロフィールやコメントが消えても、すでに正常取得した履歴は一時エラー・404・取得失敗だけで消さない。「退会確認済み」「現在取得不能」「削除確認済み」は区別する。
5. 本変更は利用停止時の保存挙動であり、本人からの正式な個人データ消去依頼を拒む「永久保存」を意味しない。消去依頼・保存期間・本人確認・プライバシー告知は別の管理フローで扱う。
6. 削除済みコメント本文の版管理、プロフィール物理DELETE時のFK CASCADEからの完全保護、退会者一覧の履歴表示、取得速度の全最適化は今回未実装であり、別件の検証・修正対象。

## 変更範囲と確認方法

- `supabase/functions/insight-access/index.ts` の `owner-remove` にある公開参加者DELETEを、共通の非公開化upsertへ統一する。
- 退会の既存セッション失効・Reader token失効・保存用プロフィールの監視停止は変更しない。
- 回帰テスト：`node --test tests/insight-withdrawal-retention.test.mjs`。
- 本番への適用にはGitHub main / Pages CI と **`insight-access` Edge Function の別途配備** が必要。GitHubへのcommitだけではEdgeの実動作は変わらない。
