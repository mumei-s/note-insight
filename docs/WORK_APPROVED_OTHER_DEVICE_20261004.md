# 承認済み申請の別端末での本人確認

INSIGHT 2026.10.04.2。本人通知 3.6.25 / ダッシュボード 1.6.4 / DM 1.4.10 は変更しない。

## 原因

OWNER承認後、本人確認をまだ完了していない申請は `approved` のままである。
別PCの「機種変更・再ログイン」は `active` だけを受け付けていたため、正しいnote URLでも `INSIGHT_MEMBER_NOT_ACTIVE` を返していた。
旧端末の申請トークンがない新端末では、承認済みの初回本人確認を続ける入口がなかった。

## 修正

- `insight-recovery` の開始・本人確認は `approved` と `active` を対象にする。
- 開始では承認状態を維持し、新しい端末に確認コードと続行情報だけを渡す。
- noteの該当本人プロフィールに最新コードがあると確認できた後だけ、同じ申請IDを `active` にし、既存の参加者行を有効にする。既存のプロフィール作成トリガーも動く。
- 承認待ち・却下・利用停止・未申請では開始しない。OWNERの承認を省略しない。
- 本人確認中の利用停止や確認コードの再発行を、条件付き更新で検出する。古い確認操作が新しい確認コードを消したり利用停止を解除したりしない。
- セッションは端末ごとに追加し、他端末のログインを失効させない。
- 画面は承認済みなら「本人確認を続ける」と案内する。再申請・再承認は不要。

## 参加者の操作

新しい端末の「機種変更・再ログイン」に同じnote IDまたはクリエイターページURLを入力。
発行した新しいコードを一時的にnote自己紹介欄へ入れて保存し、元の画面で「保存したので本人確認する」を押す。
確認後は自己紹介欄のコードを削除できる。以後はPC2台とスマホで同じアカウントを使える。
新規取得には、取得するブラウザ側の対応ツールと連携が引き続き必要。

## 検証

`tests/recovery-other-device.test.mjs` で、承認済みの本人確認開始・本人確認前のセッション未発行・初回の利用開始・コード再使用拒否・未承認拒否・別プロフィール拒否・PC2台とスマホのセッション維持・途中の利用停止・新しい確認コードの保護を検証する。
認証ストレージの既存回帰テスト、production build、機能境界チェックも実施する。
実参加者のコード発行・note自己紹介欄変更・本人確認の完了は参加者自身が行う。
