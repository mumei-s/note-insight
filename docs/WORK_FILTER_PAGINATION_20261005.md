# 通知フィルターのページ送り再修正 2026-10-05

実機の「先頭12件を隠した後、スクロールで先へ進めない」を未解消として扱う。開始時のmainは `6c9b3ebb09b5400587ff130556e4ea9b5a97a1f5`。

以前の補助領域はoverflow:autoの最初の要素を選び、内容に合わせて伸びるリストのclientHeightを基準にしていた。非表示後の短いリストを基準にすると、外側の固定スクロール枠より補助領域が小さくなり、スクロール範囲が作られない。

4.2.3では行の親から実際のスクロール範囲を持つ祖先を選ぶ。実範囲がまだない場合は外側の枠を基準にして高さを確保する。末尾の通知がフィルター対象の場合、その元のDOMノードだけを透明な1pxの測定可能な要素として保ち、内容・操作・アクセシビリティは隠す。公式が行自身をページ末尾の監視対象にする場合の判定を消さないための対処であり、Androidの公式DOMから監視方法を取得したわけではない。

「続きへ」は同じ公式スクロール枠の末尾へ移動する。通知APIの別走査、再保存、フィルター解除は実行しない。次の行が追加されたら判定を再適用し、旧末尾行を完全に折りたたむ。OFF・離脱時は元の属性とスクロール設定を戻す。
