## 実機報告と原因

添付1000015345の「現在地・公開日別の反応」は、別HTML `install-free-analysis-v3.html`。
APIの本番応答は `creator.followers / creator.following` と `stats.officialFollowers / stats.officialFollowing` を返すが、画面が存在しない `counts / summary` のみを読んでいた。

実際の公開プロフィール取得ではフォロワー2,132人・フォロー883人を確認。確認時の保存済み公式分析用フォロワー数も2,132人だった。人数は変動するため固定表示しない。

## 分離した修正

1. 公開分析API：既存の数値フィールドを維持し、欠損をnull・実測0人を0で返す `creator.publicCounts` と確認時刻を追加。返されたnote IDと認証済み本人IDが異なる場合は拒否。本人認証・参加者別保存先・記事同期処理は変更しない。
2. 公開分析HTML：実APIのフィールドを参照。保存値／確認時刻を表示し、人数を先に更新してから既存の記事詳細同期を実行。同期失敗でも取得済み人数を保持。連打を抑止。
3. 同じ画面のアカウント境界：保存ログイン復元後にキャッシュキーを確定し、前アカウントの遅い応答・異なる本人IDを描画／保存しない。明示ログアウトから勝手に復帰しない。

色・グラフ・集計・通知・DM・Social・公式Dashboard Reader本体は変更しない。

## 検証範囲

- 本番形式、0人・欠損・不正値、保存値先行表示、再読込、更新クリック、記事同期失敗、アカウント切替、明示ログアウト、展開／収納、運営者と参加者の本人スコープを実コードで検証。
