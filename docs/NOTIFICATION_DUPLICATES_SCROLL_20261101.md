# 本人通知：重複表示とフィルター後の下端停止

対象：note.com のネイティブ🔔一覧。開始点は `ed7c4cf564fd0737bc9900b1da0987b5c3d1d7c0`。

## 原因と変更

- フィルターで追加ページが折り畳まれると、note の追加読み込み用 sentinel が IntersectionObserver の 200px 範囲内に残る。スクロールイベントだけでは交差状態が変わらず、従来は「続きへ」を押すまで次の読み込みが始まらなかった。
- 4.2.15 では一覧下端の下向きスワイプ／ホイール操作に応じ、既存の明示操作と同じ処理で sentinel を一度範囲外へ出して戻す。touch/wheel は passive で、通常スクロールを禁止しない。同じ指の操作からページ取得を繰り返さず、待機・合成 scroll・上向き操作では始めない。
- フィルターON時、同一通知ID、または記事／特定コメントの対象URL・通知本文・人物画像列・日時が完全一致する複数人物のスキ通知だけを重複判定する。対象を証明できないコメントや返信は残す。
- React の行・sentinel は削除／複製せず、既存の非表示マーカーを共用する。OFF時は元の一覧表示に戻す。通知保存や取得APIは変更しない。
- 通知ID、画像URL、日時が同じ行の中で更新された場合も再判定する。重複判定のための通信は追加しない。

## 検証

`tests/notification-filter-gesture-dedupe-v4215.test.mjs` は6件成功。変更前の4.2.14では同じテストのうち5件が失敗し、スワイプ停止と重複表示を再現する。

既存のフィルター／ページング／行ごとの処理予算、実Reader連携と通知保存の検査も継続する。実機のAndroid Edge・iOS Safari全機種をこの環境で操作したとは主張しない。
