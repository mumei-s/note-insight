# 巡回BOOST 専用アプリ復旧・完成プロンプト（2026-09-16）

この文書を最新版要件・実装正本として読み、`mumei-s/note-insight` の最新 `main` から作業すること。古いローカル状態で上書きしない。既存の INSIGHT・本人通知・名鑑・極薄通知系・他userscriptは壊さない。

## 0. 最重要方針

現在の失敗した構成（GitHub Pages の `boost-app` から note.com へ `window.opener` / postMessage / GM_xmlhttpRequest で跨いで操作）は廃止する。

Android Edge + Tampermonkey 実機で確実に動かすため、巡回BOOSTは **note.com 同一オリジン上の専用アプリモード** にする。

専用アプリ入口は次で固定する。

`https://note.com/?boost_app=1`

Tampermonkey userscript は通常の note.com 閲覧では UI を一切出さない。`boost_app=1` が付いた時だけ `document-start` から専用アプリUIを描画し、noteのAPIへ通常の same-origin `fetch(..., {credentials:'include'})` で通信する。

つまり：

- 通常note画面：巡回BOOSTの♡、タブ、パネル、ランチャーを一切表示しない
- 専用URLだけ：画面全体を巡回BOOSTアプリとして使う
- GitHub Pages版 boost-app は互換案内ページに下げるか、専用URLへの案内だけにする
- INSIGHTには統合しない
- INSIGHT参加者へ自動配布しない
- Tampermonkey側は1本だけ

## 1. なぜこの方式にするか

これまで以下が失敗した。

1. `github.io` → `note.com` を別タブで開き `window.opener` + postMessage で接続
   - Android/Edgeで opener が切れ、noteトップだけ開く
2. `github.io` 上で Tampermonkey + `GM_xmlhttpRequest` により note API へ直接通信
   - 実機で通信タイムアウト。Cookie/拡張機能/クロスオリジン依存が不安定

今後はこれらを再利用しない。同一オリジンで完結させる。

## 2. userscript

既存配布URLは維持：

`https://raw.githubusercontent.com/mumei-s/note-insight/main/public/note-boost-v531.user.js`

バージョンは次の完成版として **v6.2.0** 以上へ上げる。

メタデータ要件：

- `@match https://note.com/*`
- `@grant none` を基本にする（same-origin fetchのため）
- `@run-at document-start`
- `@updateURL / @downloadURL` は現行配布URL維持

起動条件：

```js
new URL(location.href).searchParams.get('boost_app') === '1'
```

この条件以外では何もしない。既存note DOMにランチャーやパネルを追加しない。

## 3. 専用アプリUI

`boost_app=1` の時だけ、noteトップが見える前に専用UIへ置き換える。SPA遷移・再描画でもnoteトップへ戻らない。

スマホ最優先。横スクロール禁止。

必須UI：

- ヘッダ：`巡回BOOST`
- 巡回元入力：
  - 記事URL
  - マガジンURL
  - `#タグ`
  - クリエイターID / プロフィールURL
- 開始 / リセット
- 現在の進捗
- 1h / 24h リミッターと解除時刻
- 現在のクリエイターカード
- `戻る` / `次へ` は常に同じ位置・同じ文言
- `♡スキ`
- `実記事`
- `プレビュー`
- `👤クリエイター`
- `📚マガジン追加`（上部にも配置）

### 現在人物のスキ状態

必ずどれか1つだけ：

- `💗 この人は元からスキ済み`
- `♡ この人は未スキ`
- `❤️ この人は今回スキ済み`

前の人物の状態を次の人物へ持ち越さない。

## 4. 実記事 / プレビュー

### 実記事

`実記事` は note の本物の記事へ同じタブで遷移。

遷移前に巡回状態を localStorage に保存。ブラウザバックで `?boost_app=1` の専用アプリへ戻ったら同じ人物・同じ位置を復元。

### プレビュー

`プレビュー` は専用アプリ内のモーダル。

note API または同一オリジン記事HTMLからタイトル・アイキャッチ・本文を表示。テキストだけに潰さず、画像・見出し・リンクなどを読みやすく表示する。ただし script/style は除去。

## 5. クリエイター情報

専用画面に以下を表示：

- アイコン
- 表示名
- @ID
- プロフィール文
- フォロワー数（取得できる場合）
- フォロー数（取得できる場合）
- 記事数（取得できる場合）
- 公開記事一覧

名前・アイコン押下でプロフィール実ページへ移動可。

記事一覧は `記事スキ数の多い順` を基本表示にする。各記事にスキ数を表示し、タップで実記事へ移動。

## 6. クリエイターIDを巡回元にした場合

IDをタグ扱いしない。

例：

- `Sui_ai_drawing`
- `@Sui_ai_drawing`
- `https://note.com/Sui_ai_drawing`

はすべてクリエイター入力として扱う。

そのクリエイターの公開記事を可能な範囲で全ページ取得し、**記事スキ数が多い順**で巡回キューを作る。同スキ数なら新しい記事優先。

画面に `記事スキ数順` と明記。

## 7. #タグ巡回

一般検索 `/api/v3/searches?q=` は絶対に使わない。

タグ専用：

`/api/v3/hashtags/{tag}/notes?order=new&page=N`

を使う。

例：`#王子ごっこ` は `王子` という本文/タイトル/類似タグを拾わない。

- 完全一致のタグ母集団
- 自分を除外
- クリエイター重複なし
- 1人につき代表記事1件

`#はじめましてnote` が0件になる不具合を再発させない。

## 8. 記事URL巡回

記事URL → その記事のスキユーザー一覧 → 人物重複なし → 各人物の代表記事1件。

代表記事は基本的にそのクリエイターの最新公開記事。ただし取得不能時は安全にスキップ。

## 9. マガジンURL巡回

マガジンURLは「追加先」ではなく巡回元。

そのマガジンに載っている記事のクリエイターを抽出し、人物重複なしで代表記事へ巡回。

## 10. 50件単位と自動続行

表示・処理単位は50件でよいが、50件で終了扱いにしない。

50件を最後まで進めたら次の50件を自動取得できる。最終ページまで続ける。

対象：

- #タグ
- 記事URLのスキユーザー
- マガジンURL
- クリエイターIDの記事一覧

同じ人物を次バッチで再登場させないよう、巡回元ごとの `seenCreators` を永続保存する。

## 11. マガジン追加

元から追加済みの✔判定は維持。

ツールからの追加は必ず：

1. 編集可能マガジン一覧を取得
2. 実サムネイルを表示
3. サムネイルタップでそのマガジン実ページへ移動
4. `追加` 押下
5. note APIへ追加
6. 再取得
7. 本当に追加済みになったことを確認
8. 確認できた時だけ `✔追加済み`

送信しただけで成功表示しない。

過去に実動していた payload / endpoint を最新main履歴から比較し、現行noteで通る形を使う。推測だけで `note_key` を削除/追加しない。

## 12. スキ安全設計

絶対に誤って unlike しない。

- 事前に現スキ状態を取得
- 既スキならPOSTしない
- 未スキの時だけPOST
- POST後に再取得して `liked=true` を確認
- 反映確認できた時だけ `今回スキ済み`

403 / 429 で停止保護。

暫定安全上限：

- 18回 / 1時間
- 80回 / 24時間

これはnote公式値ではなく、ツール側の保守的安全値として表示する。

マガジン追加も同じ安全上限・403/429保護。

## 13. 状態保存

localStorageで巡回状態を保存：

- source
- sourceType
- queue
- index
- page/cursor
- seenCreators
- like状態
- 今回スキ履歴
- 追加済み確認
- リミッター履歴

画面を閉じても、実記事へ飛んでも、ブラウザバックしても復元。

リセットを押した時だけ対象巡回状態を消す。

## 14. タイムアウト対策

アプリ起動自体に通信ブリッジのREADY待ちを設けない。

同一note originなので、`fetch` が失敗したらHTTP/JSONエラーをその場に表示する。

`通信タイムアウト`だけを12秒/20秒待って出す旧方式は削除。

fetchには必要なら AbortController 15〜20秒を付けるが、UIに：

- ログイン未確認
- API 401/403/429
- APIのエンドポイント不一致
- ネットワーク切断

を分けて出す。

## 15. 起動時診断

専用アプリ起動時に自動で：

1. 現在ログイン中のnoteアカウント取得
2. @ID表示
3. API疎通確認
4. スキ/マガジン追加用APIの「読み取り側」確認

ここが通るまでは操作ボタンを有効にしない。

ログインしていない場合だけ `noteへログイン` を出す。

## 16. GitHub Pages版

`https://mumei-s.github.io/note-insight/boost-app/` は旧本体として使わない。

役割は「専用アプリを開く」入口だけにする。押すと：

`https://note.com/?boost_app=1`

へ遷移。

カード貼り付け用OG画像は、狭いnoteカードでも読めるよう：

- `note巡回BOOST`
- `専用アプリ`

程度の大文字だけ。

## 17. 検証

最低限以下をテストしてから公開済みと言うこと：

- userscript構文
- npm build
- 既存INSIGHT回帰
- 通常 `https://note.com/` で巡回UIが一切出ない
- `https://note.com/?boost_app=1` でnoteトップではなく専用UIが出る
- 起動診断でログイン中@IDが取れる
- #タグが専用APIで取れる
- クリエイターIDがタグ扱いされない
- 戻る/次へ統一
- 実記事→戻るで位置復元
- マガジン一覧・サムネ・既存✔
- 追加操作後の再確認
- 既スキ時にPOSTしない
- 50件後の続行

Android Edge実機を自動環境で直接確認できない場合は、コード/テスト成功と実機未確認を分けて報告する。実機成功を捏造しない。

## 18. 今回の禁止事項

- INSIGHTへ統合しない
- 参加者へ配らない
- note画面に常駐ランチャーを出さない
- GitHub Pages→noteの opener/postMessage bridgeへ戻さない
- GitHub Pages上のGM_xmlhttpRequest依存へ戻さない
- 一般検索APIを#巡回に使わない
- 成功確認なしでマガジン追加済み表示しない
- 50件で全件終了扱いしない
- 古いmainへ巻き戻さない

## 19. 完了条件

ユーザーはTampermonkeyの現行配布URLを1回更新するだけ。

その後は専用入口：

`https://note.com/?boost_app=1`

を開くだけで、noteトップへ飛ばされず、巡回BOOST専用画面が起動し、ログイン中noteアカウントで巡回・スキ・記事閲覧・プレビュー・クリエイター記事一覧・マガジン追加が行えること。
