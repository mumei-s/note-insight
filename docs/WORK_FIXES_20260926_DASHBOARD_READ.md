## 2026-09-27 再読込のたびに記事・メンシプを再巡回する不具合（1.5.6）

最新の利用者報告は「読み込んで、再読込して下さいって出て、やっても往復を繰り返す」。開始時main `374ae15e23e63abb4c880b6f6642493f8a4eda8c` を取得。公開許可は既にあるため追加確認せず修正公開を進める。

### 確認した原因と修正

- 開いたDOMをWeakSetで記憶していたため、排他パネルの再描画でDOMが置換されると既読パネルを未読扱いにした。内容タブ・パネル識別子・見出しを使って既読を保持する。追加ページボタンのみ取得行の変化を進捗として認める。開かないパネルを新しいDOMへ置換しても成功と判定しない。
- `role=progressbar` を全て通信中と判断していた。数値表示用の `aria-valuenow` があるグラフを待機対象から除外し、実際の `aria-busy` と不定の読込表示は待つ。過去28日間・記事数順等の表示条件ボタンを展開しない。
- 全パネルの読取成功後まで収集結果を保持せず、途中失敗の後は手動操作で最初から巡回していた。安定した各パネルの読取直後に結果・既読・処理中の対象を保持し、続きから再開する。
- 保存するpayloadと保存済みsnapshotIdも保持する。送信失敗は同じ取得結果を送信し直し、保存後の照合失敗は同じsnapshotIdの照合だけを再試行する。どちらも内容タブを再クリックしない。
- 現在のタブのsessionStorageにも10分間のチェックポイントを保持する。接続情報・表示期間・pathnameのSHA-256が一致する場合だけ復元。トークンそのものを複製しない。表示期間がページ描画後に現れる場合も復元を維持。Web Crypto/Storage利用不可時は同じページ内のメモリ再開に限定される。
- `READ_WAIT` / `PANEL_NOT_OPEN` / `TAB_NOT_OPEN` / `SAVE_COUNT` 等の段階を表示し、取得済み件数を残す。ボタンは「続きから読込」「保存を再試行」「保存確認を再試行」に分ける。エラー本文を2行で切り捨てない。
- 完了判定は引き続き本人一致・DB保存件数・日別件数・合計の一致が必要。開けないパネルや日別PV未取得を「同期完了」と偽らない。owner専用の分岐は増やしていない。
