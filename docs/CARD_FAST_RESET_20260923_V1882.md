# 極薄＋通知 18.8.2 — 初期化と高速化

## 最新のユーザー指示

- 失敗時は途中再開より初期化してやり直す。
- さらに高速化する。
- 停止地点は「3回目」という回数ではなく、約200枚として調べる。
- 18.8.1のパネル縮小と、重複人物の#記事優先は維持する。

起点は開始時の最新main `8332268d3a17653bcbaab091057fca03a8d09dab`。
旧チェックアウトを更新元にせず、新しい作業ツリーで変更した。

## 確認できた問題

1. 初期化は `run.images` に記録された完了画像だけを削除し、`run.pending.slots` の未完了画像を残して投入記録を消していた。
2. 次の80枚を自動準備して画像選択待ちに入ると、別モジュールの初期化が本文保護の排他制御に弾かれていた。
3. 初期化後は同じ記事のPNGを毎回ネットワークから再取得・再描画していた。
4. 本文の控え3世代それぞれに同じ対象一覧を丸ごと保存していた。数百件になるほど保存容量・JSON処理が増える。
5. アップロード以外の例外は投入段階と開始枚数が診断に残らず、約200枚地点の原因判別が難しかった。

「200枚で停止させる上限」は配布コードにはない。端末の実行ログ・実通信エラーを取得できていないため、上記を実機停止の唯一の原因とは断定しない。

## 変更

- 初期化は画像選択待ちを解除し、準備済みファイルを解放してから開始する。
- 通信中は最大60秒待ってから初期化可否を判定する。通信が続いていれば削除せず停止する。
- 完了画像に加え、今回の投入IDが確認できる未完了画像も一括削除。元本文・元画像を維持し、保存成功後に作業記録を消す。
- 投入記録が不明な画像が残る場合は勝手に削除せず、具体的な理由を表示する。
- 本文の控えは保持。対象一覧を記事・datasetId単位で共通化し、参照がなくなった同一記事の一覧だけを整理する。書き出し時は一覧を含む完全なJSONになる。
- 不変の対象一覧を本文控えのたびに再解析・再シリアライズしない。
- PNGのCacheStorageを追加。同じ記事・タイトル・作者・サムネイル・アイコンなら再取得と再描画を省く。12時間、最大512件、1件128KiB（計最大64MiB）。画像Blobを全件メモリに保持しない。
- キャッシュ失敗・非対応時は従来の画像生成へ戻す。画像内容が変われば別キー。通信失敗で画像を代替描画したPNGは保存しない。
- リンク確認は画像ID索引を利用し、同じDOMへの軽量化属性の繰り返し書き込みを減らす。
- 失敗時に処理段階・開始枚数・版・通信情報を記録する。読み取り専用のDOMException.messageを変更せず、停止処理を完了する。
- PNG860×140、最大80枚ずつのnote標準画像投入、自動再読込なしを維持する。

## 検証

`node --test tests/card-safety-v188.test.mjs`：38件成功。
`node scripts/build-card-userscript.mjs --check`：生成物一致。
`node --check public/note-card-batch-bridge-v610.user.js`：構文検査成功。

追加した10件では以下を確認した。

- 80 + 80 + 40枚成功の200枚地点で通信失敗を注入。初期化で成功200枚と未完了40枚を除去し、原稿・通常画像を保持。
- 画像選択待ちを初期化で解除し、ファイル参照と入力の差し替えを解除。
- 通信中・記録にない画像がある場合は本文と作業記録を保持。
- 307件の対象一覧を3世代の本文控えで共有し、対象一覧も復元可能。模擬データの控え保存量が旧形式の65%未満。
- 同じdatasetIdが再利用されても古い控えの一覧を上書きしない。
- キャッシュから画像を再利用し、行番号変更時は新しいファイル名を使う。タイトル・記事・画像変更時には再利用しない。
- 512件・128KiBのキャッシュ上限と、保存失敗時の通常動作。
- 他の記事や参照中の本文控えの対象一覧を削除しない。
- 12時間経過したキャッシュを再利用しない。
- 200枚後のDOMExceptionを正しく終了させ、投入段階を記録する。

既存の307枚連続投入、本文697文字の復元、保存失敗時の停止、#優先、パネル縮小等の検証も維持。
これらは模擬環境であり、Android実機やnoteへの実アップロード成功を示すものではない。

## 更新と使い方

noteの下書き保存完了を確認してから18.8.2へ更新し、編集画面を開き直す。
失敗後は「初期化」→「開始」でやり直せる。初期化は確認できる今回の生成物だけを削除する。
同じ内容の画像はキャッシュから再利用するが、noteへの画像アップロードは引き続き必要。
約200枚での実機停止解消は未確認として扱う。
