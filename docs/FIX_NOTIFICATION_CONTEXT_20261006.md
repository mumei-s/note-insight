# 通知・スキ履歴の対応状況とコメント本文（2026-10-06）

## スキ履歴

現行 MemberInsightUnifiedV4 の各クリエイター行に「対応済みにする」「対応済み・未対応に戻す」を追加。既存の全件・未対応・対応済みフィルターに連動する。insight-member-history は認証された member_id と記事・スキした人物を検証してから既存の insight_manual_completions に保存する。既存ステータス RPC の creator_urlname='ss_yr' は互換キーで、所有者の判定は認証済み member_id。書き込み失敗を閲覧キャッシュから成功として返さない。

## 本人通知

対応済みは本人の通知IDを確認してから通知の event_identity（旧記録は row ID）に結び付けて保存する。未対応への復帰も可能。ページを閉じても保存状態を保持する。

返信・コメントスキの本文は通知URLの c パラメーターと記事キーで完全一致照合する。本人の保存済みコメントを優先し、見つからなければ公開コメントと返信を取得する。取得した本文を通知 meta に保存して次回から再利用する。照合中は小さいスピナーを表示する。対象ID・対象コメントのリンクも表示する。通知の案内文や人物・時刻だけの近似一致を実本文に転用しない。取得不能なら原通知を保持して再試行できる。

旧DOM拡張は現行Reactのコメント欄に介入しない。本文取得と対応済み保存が同時に完了しても別の項目を上書きしない。

## 分類

記事名を挟む記事更新を認識し、記事投稿・更新の分類を本人通知に用意する。実データで確認できる user_badge と thank_you_message を「バッジ獲得」「購入記事のメッセージ」に追加する。DBの最終トリガーも新しい分類を保持する。

自動再分類は新ルールで未処理のその他だけ、手動「未分類を再分類」は確認済みの未分類も再確認する。既存の通知IDによる復元と本人のスコープを保持する。本文不足の旧通知は推測分類しない。

本番で確定できた2件を修復し、対象アカウントのその他は208件から206件になった。原本文・所有者・時刻は維持した。
