## 保存API

- 旧コピーとの本文照合をGET URLのbodyフィルターから外した。同一本人・会話・送信日時の候補だけ取得し、本文はサーバー内で照合する。長文URLの上限と私的本文のURL混入を回避する。
- 候補が3件の上限に達した場合は一意と断定せず、旧履歴を隠さない。既存owner本文・送信者・添付・日時の保持と本人別scopeは維持する。
- 失敗時は本文・相手・URL・認証情報を出さず、固定の処理段階も記録する。
- 本番v6で既存の本人長文1件を同じ識別子で再送し、HTTP200・保存確認1件を確認。診断用の短時間tokenは失効済み。これは元の失敗batchの再送確認や新しい未保存本文の回復確認とは区別する。
- feed v6は`lastMessageSavedAt`を追加し、整理済みコピーを除いた本人本文の実保存時刻を返す。一覧だけのrunや別本人の保存日時を混ぜない。

## INSIGHTのDM表示

- 不正なHTTP200 JSONを空の成功へ置き換えない。再確認の失敗時は確認済みの相手・本文を保持する。
- 明示的な更新は古い取得を中断して最新を再取得。相手の選択と開いた履歴を維持する。
- 本文のページ欠損・重複による件数不一致を検出する。確認済み本文を欠けた途中結果で上書きしない。
- 件数未確認を「本文未保存」と表示しない。保存エラーは過去の完了印より優先する。
- 本人切替時にstateとbridgeを切り替え、非表示中の通信と遅い応答を停止する。
- 「本文保存」は新しい実保存時刻を優先。旧API応答の場合は成功したReader保存時刻へ戻し、一覧だけの最新run時刻は使用しない。

## DM Reader / Network

- 本人確認はfetch・JSON・abort無視のいずれも12秒で打ち切り、確認できない本文を別本人へ保存しない。停止後の遅い確認で取得を再開しない。
- 最初のDM通信やSPAで入った直後の通信も捕捉する。通常のnote通信は元のfetch/XHRの引数・戻り値・例外を保持し、本人確認・保存を開始しない。
- 保存500の未確認batchは永続キューと元の保存境界を保持。復旧後の同じ本人の再送で確認できた分だけ境界を進める。
- 500会話の処理上限は1回の仕事量として維持し、後方会話を捨てず次回へ巡回する。一覧登録も500件ずつ送る。今回本人は20会話なので、204回の500をこの上限のせいとは扱わない。
- 部分描画や次回一覧が空でも本人別の保存済み会話候補から再開する。失敗状態を「全会話保存完了」と併記しない。
