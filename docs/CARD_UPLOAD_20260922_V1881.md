# 極薄＋通知ツール 18.8.1

## 診断

ユーザーから「307件の成功実績があるのに、現在版は3回目の画像投入で停止する」と報告。
成功実績のある14.3系と18.8.0の実装を比較し、次の不具合・差分を修正した。
端末の実行ログを直接取得できていないため、実機での停止原因を一つに断定していない。

- 画像投入後も10分の「画像選択待ち」タイマーが動き、アップロード完了待ちを途中で中断し得た。
- 画像以外のHTTP失敗、前回のエラー表示も今回の画像アップロード失敗として扱っていた。
- 成功版にあった画像表示の負荷軽減が抜け、投入ファイルも処理後に解放していなかった。
- 一部失敗の投入記録を保持した後、成功済み画像を残して失敗分を再準備する経路がなかった。

## 修正

80枚単位、860×140 PNG、noteの「＋→画像」を利用する操作を維持。
選択待ちタイマーを投入開始時に解除し、画像を含む要求だけを監視する。
既存エラーを除外し、進行中の画像通信・画像増加を待ってから失敗を判断する。
完了待ちは最大30分。自動再読み込み、画面遷移は行わない。

追跡できる生成画像だけを遅延表示・非同期デコードの対象にする。
サムネイルとアバターのデコードを縮小し、完了後に投入ファイル参照を解放する。

失敗が記録され、通信停止と画像状態の安定を確認できる場合、「画」で成功分を回収する。
今回の投入IDと並び順が確認できる未完了画像のみ取り除き、保存を確認してから不足分を準備する。
元本文、元画像、成功済み画像は保持する。順序不明時は変更せず停止する。
18.8.0の失敗診断記録も判定に利用する。

#抽出は実際にタグで見つかった記事を保持する。
URL側の人物と重なれば、入力順・人数上限・選定モードにかかわらず#記事を採用する。
選択済みの人物について、必要な場合は#の後続ページでも重複を確認する。
URLのみの人物は従来の選定モードを維持する。複数#の候補は先に見つけた記事を採用する。

パネル幅を250pxから230px、入力欄の高さを58pxから42pxに縮小。
後から追加されるスタイルに負けない指定とし、選定ボタン27pxを維持する。

## 検証

既存19項目に9項目を追加。ソースを実行するモック環境で28項目成功。

- 同じファイル入力へ307枚を80/80/80/67枚の4回で投入し、画像ID・リンク・保存・ファイル解放・タイマー解除を確認。
- 画像以外のHTTP500と前回の通知表示がアップロードを止めないこと。
- 0枚失敗・一部失敗の再開、元本文と元画像保持、進行中通信がある場合の再投入阻止。
- #/URLの両入力順、人数上限後の重複、#の2ページ目での重複、URLのみの選定条件。
- 697文字の本文復元、容量不足時停止、古い本文位置の拒否、自動再読み込み不在などの既存保護。

307枚の検証は実処理関数を使うシミュレーションであり、noteへの実アップロードではない。
Android Edge / Tampermonkey実機の確認は未実施。GitHub Actionsで実際のNode検査・既存テスト・生成物一致を検証する。
