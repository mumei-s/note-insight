# 通知の保存待ち停止 — 本人通知3.6.15

## 報告と確認範囲

添付1000015368.jpgは「読込69/69・保存確認0」、操作ボタンは「停止」。画像だけでは端末上で止まった通信・保存先の応答内容までは特定できない。
最新main `489994a801358a7424b571c74ca5782a48a19048` を基点に確認した問題：

- 保存リクエストはGMのコールバックだけを待ち、返されるPromiseを処理していなかった。拡張のtimeoutコールバックが来ないと永久待機。
- noteの本人確認・通知取得・応答本文に期限がなく、「停止」はフラグを変えるだけで待機を解除しない。
- Readerの失敗通知にscanning=trueが残り、さらに5秒ごとの自動確認がエラー表示を消す。
- 操作パネルは保存待ちも「読込」と表示し、エラー詳細を1行で切っていた。

## 分離した変更

1. network：Promise/コールバック両対応。note取得は本文を含め15秒、保存通信は45秒で待機解除。停止時は進行中通信を中断し、遅い応答を無視する。未確認通知・保存境界は維持し、取得済みの通知から再開。
2. reader：失敗時に読込中状態を解除。通信の一時失敗のみ30秒→60秒→120秒→240秒→最大300秒の間隔で自動再試行。連携・権限等のエラーは勝手に繰り返さない。手動の再試行は即実行。
3. controls：保存待ちは「保存先を確認中」。失敗理由と保存確認件数を折り返して表示。停止・再試行の既存ボタンを利用。

filter4.1.4、通知分類、DM1.4.9、Dashboard1.6.2、分析には本体変更なし。サーバー・DB変更なし。公開版の通知ラッパー3.6.15と@requireの更新で配信する。
