# 2026-10-17 起動・復帰時の不要な取得

ユーザーの「開くたびに履歴全部を読み込むぐらい遅い」「またギガ超える」を最優先に継続。本体2026.10.17.1、通知3.6.38・Dashboard1.7.3・DM1.4.11は据え置き。

## 先行する画面側の修正

- 同じtoken/noteIdの認証確認・プロフィール保存イベントではdocumentを再読み込みしない。本当のアカウント切替・token変更・ログアウトは従来どおり切り替える。明示ログアウト時のtoken削除は生の保存レコードから所有者を確認し、別アカウントを消さない。
- 保存済みtokenで本体を開く初期状態ではAppの認証確認を待ち、一瞬だけアクセス画面を起動して同じ認証通信を追加しない。手動アクセス・失効時の経路は維持する。
- Unifiedの初期スキ表示ではsummaryと表示中のスキ100件だけ取得し、非表示の分析・コメント・通知・旧履歴コンポーネントを起動しない。記事分析を選んだ時にdashboardOnlyを指定し、別の公開コメント/スキ巡回を起動しない。
- Liveの本人情報確認は、重いmember/dashboardから認証済みaccess/sessionへ変更。active/noteIdとtoken・scope・request順序を検証してから本人表示に採用する。
- 60秒以内のvisibility/pageshow/online復帰は認証確認だけにし、全sceneのrevisionを増やさない。60秒超の確認、15分更新、明示更新・保存成功時の更新を維持する。同じ復帰イベントの重複更新も抑える。
- recent通知が返っただけで、進行中の同一ページ取得をabortして最初からやり直さない。表示本文・著者・分類・状態等に本当の差分がある場合は再確認し、遅い古い応答で上書きしない。

前回起動の古い保存コピーを最新扱いする変更は行わない。確認済みの同一session表示は保持し、本人切替や不正応答を受け入れない。機能ごとに別commitとして保持する。

## 検証

新規回帰検証で非表示API呼出しゼロ、同一session再確認時のreloadゼロ、変更のない通知のfull取得1回、短期復帰でrevision不変、本人切替・遅延応答・無効200の拒否を確認する。旧実装で該当検証が失敗することも確認。Pages workflowへ新規検証を追加し、隔離した先行公開treeの既存全group・build・公開ファイル一致を確認する。

元のAndroid端末での実操作と通信量計測は未確認。速度や契約通信量の保証として扱わない。

## 保存先側の継続調査

通知feedは表示100件へ切る前に全履歴をEdgeへ転送していた。DB側でページ・集計を作り、ページとpreviewだけ返すRPCを別作業で検証中。初期案は本番read-onlyで41.39秒、二段化案も16.87秒のため、先行公開には含めない。全履歴を転送するfallbackも新設しない。速さと既存dedupe・分類・件数・権限の同値性が通るまで配備しない。

コメントのcold取得は50件probe＋500件単位、DMの選択会話も本文ページを必要に応じて取得する。今回はこれらの保存先APIに内容revisionがなく、前回起動データを最新と誤認させる危険があるため、cold全件取得の契約自体は変えていない。通知返信のlocator変更時の本文保持条件も別途確認対象。掲示板返信の実本文・元IDが保存されていない問題は未解決のまま。
