# 本人通知の再試行待機を維持する

Reader 3.6.38。記事へ移動して🔔へ戻るたびに、自動取得の `retryAt` と失敗回数が0に戻っていた。HTTP 429/503を再現した検査では、表示上は30秒の待機中でも約1秒で次の要求を始めていた。

自動再表示では有限の通信待機と失敗回数を維持する。通信が成功した場合と利用者が明示的に再試行した場合は従来の解除動作を維持する。期限なしの連携エラーは、別アカウントや連携修復後を妨げないよう再表示時に解除する。

追加の本人取得・保存キー・通知破棄はない。現在のnetwork APIが検証済み本人IDをReaderへ公開しないため、有限の通信待機は同じ実行中のタブで共有する。最大5分の待機を手動の再試行で解除できる。

新規 `notification-reader-retry-cooldown-v3638.test.mjs` は6件成功。変更前では3件が失敗し、連続した記事復帰・500ms以上の離脱から待機解除を再現する。既存のReader、公式ページ、保存・本人境界と統合検査37件も成功。
