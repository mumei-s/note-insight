# 先頭ページ全件フィルター時のスクロール復旧 — 本人通知3.6.26

開始時main: `12a9fcfb35e3ddc9aef997590514a215609b02ab`。
実機1000015646.jpg: 読込済み先頭12件が全件対象で、一覧が空白になり下へ進めない。

## 原因と変更

行を `display:none` にすると通知一覧の高さが失われる。さらに既存のtouchmove/wheel境界ガードが、一覧内にスクロール可能要素がない操作をキャンセルしていた。

フィルター4.2.1は全件対象の場合のみ、最後の通知とnoteの次ページ読込位置の間にスクロール用領域と件数案内を残す。その間はtouchmove/wheelをキャンセルせず、note本来のページ読込へ操作を渡す。対象の通知はすべて非表示のまま。対象外の通知が追加されると補助領域を削除する。

自動スクロール・独自通知取得は追加しない。領域の高さは画面高に上限を設け、auto高さの親を基準に自己増大しない。OFF、ベル離脱、機能OFFで領域を片付ける。

変更本体はフィルターのみ。配布ラッパー・公開manifest・本体の本人通知最新版は3.6.26、filterのrequireは `?v=421`。

## 検証と限界

- 新規の先頭12件再現（GM新旧形式）は元のmainで失敗し、修正後に成功。
- 次の対象外通知の表示、連続して全件対象のページ、領域重複、ON/OFF、再入場、機能OFF、固定高さ・auto高さを検証。
- Pagesの現在の回帰ゲート165件と、追加の高さ回帰1件、OWNER DM保持5件、DM競合1件が成功。TypeScript/Viteビルド成功。
- 広めに追加実行した旧notification-dom/dock-scopeの4件は、3.6.19や古いrequire番号の固定期待で失敗。同じ4件が変更前mainでも失敗することを確認した。現行配布版の整合性はtools-release-v22で検証。
- Android実機とnoteの実際の次ページ通信は未確認。DOM再現とブラウザ実機成功は区別する。
