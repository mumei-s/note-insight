## 通知：読み取り・保存・表示

| 対象 | 実装と維持する条件 |
| --- | --- |
| 取得ページ | note自身の成功した `per` を利用し、未観測時は12件。100件指定が本番で拒否されたとは断定しない。1回の窓は最大300件。 |
| 誤った新着なし | HTTP 200でも通知配列がなければエラー。空配列なのに表示中の通知や直前の取得結果が非空なら不一致として扱う。未確認の0件を保存完了にしない。 |
| 差分照合 | 保存済みの1行目で打ち切らず、そのページ全体を調べる。既知行より下にある更新されたまとめ通知も保存対象。ページ全体が既知のとき境界とする。 |
| 再開 | 永続ジャーナル・送信待ち・確認済み集合を継続使用。保存応答の確認済みキーだけを境界に採用。停止後の再開で収集済み窓を全件再取得しない。 |
| 保存順 | 収集窓を古い側から新しい側へ保存。画面の自動スクロールは行わない。取得中断直後の未送信分は端末ジャーナルに残るため、サーバー保存完了とは別。 |
| 新着検知 | 取得したページ全体の署名が変われば15秒の抑制を解除。処理中の新しい取得結果も終了後に再確認。 |
| 保存位置表示 | 現行wrapperに欠けていたcheckpointモジュールを追加。通知IDがDOMにない場合は、保存確認済みの本文と対象URLから一致を判断。まとめ通知の件数変更は同一境界としない。 |
| パネル | ボタン32 CSS px、状態1行。読取件数・保存確認件数・途中・エラー・確認済みを区別。タッチの標準click生成を阻害しない。 |

既知種別の分類、判別不能なら「その他」に保存、分類更新時の再分類、INSIGHTで保存済み一覧を残して新着だけ即表示する前回の仕組みは維持。

## DMと🔔の表示範囲（追加画像の修正）

noteではDM画面で🔔を開いてもURLが `/messages/rooms/...` のままになる。URLだけを見てDM専用とする旧判定が残留の原因。

- DMは表示中の「通知／お知らせ」と通知一覧を独立して検出する。通知userscriptとの同時導入を前提にしない。
- 通知を開いたらDMパネルを除去し、DM巡回を中断する。DOM変更の監視側で処理するので、DM読込のPromiseが未完了でも消える。
- 保存応答・エラー・finallyの遅い進捗更新も表示範囲を再確認し、DMパネルを復活させない。
- DOM追加だけでなくhidden/class/style/aria-hiddenによる表示切替も対象。
- 通知側Reader・操作パネル・フィルターは、DM URL上でも本物の通知一覧なら動く。DMの一般的な本文・ヘッダーだけでは通知一覧と認定しない。
- 通知を閉じてDMへ戻ったときは継続できる。手動の停止状態は保持する。

## DM本文の取得

- ルームURLに対応する `{data:[message...]}`、入れ子の `room.id`、JSONスクリプトを処理。
- Reactの分割配信データ `self.__next_f.push(...)` をJSONとして解析し、本文への参照を深さ・循環制限付きで解決する。取得したスクリプトは実行しない。
- 同一オリジンのルームHTMLを先に調べ、構造化本文があれば会話DOMの長い待機より先に保存処理へ進む。通常の会話画面と不可視フレームの既存経路も維持。
- DOM本文の候補を拡張し、改行を保存。一覧プレビュー・送信ボタン・入力欄・日時単独は本文にしない。
- アカウント変更時はメモリのルームデータを分離し、保存前も本人確認する。DM専用の認証・保存先を維持。
- 本文を保存できても全ページ取得の根拠がない場合は `DM_PAGINATION_UNVERIFIED` として未完了を残す。

**実際の認証済みnote DM本文の取得成功は未確認。** 新しい形式への対応を再現データで検証したことと、本物のDMで取得成功したことを混同しない。次回は1.4.2導入後の相手別診断と本文保存件数を確認する。本人のDMを調べるために別会員の認証を流用しない。

## 分析・グラフ

- 公式Dashboardの保存データと通知照合を並行取得し、Dashboardが返ったらすぐ表示。通知最大1,000件の完了を待たない。
- 通知照合は最初の100件を先に反映し、残りは最大3ページ並行。更新中も既存の分析を残す。アカウント・トークン・要求世代が変わった古い応答は採用しない。
- Backendの `dashboardOnly:true` は公開スキ・コメント全履歴の走査を省略。旧呼び出しの分析経路は維持。最新500スナップショットを採り、古い500件への固定を防ぐ。
- スナップショットは記事保存成功後だけ `confirmed:true`。途中失敗した集計を公開しない。
- Dashboard同期は公式タブ等で取得できた場合、旧30ページのAPI巡回を重ねない。
- Proにスキ／コメントの立体円グラフ、流入の円グラフ（単位PV）を追加。
- **本人通知なし分析は別のHTML実装**なので `install-free-analysis-v3.html` も直接修正。立体SVG円グラフ、面と陰影を持つ棒、立体感のある線へ更新。
- 棒は記事本数なら「本」、記事あたり平均なら「件/記事」、間隔なら「日」、流入なら「PV」と表示。順位だけだった棒は記事名を表示。
- 公開日別の線は「その日に公開した記事の現在の累積反応」を示す。日々新たに起きた反応数ではない。日付・0起点・件数・点の詳細を表示。
- 本人通知なし分析も会員別保存済みキャッシュを先に表示。未取得のフォロワーを0人と表示しない。
- 面積や線の値を変える遠近歪曲は使わず、正確な割合・長さに陰影・側面を加える。
