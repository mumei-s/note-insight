# 2.9.8：無料記事の本文判定と要約用記事の自動切り替え

無料記事でも note v3 API が `paywall.is_simple_paid_note=true` を返すため、従来の判定では本文が存在する記事を「無料公開本文を取得できません」として画像にしていた。報告された ioRe の記事 `ne603b2b69509` で、price=0、is_limited=false、本文あり、上記フラグ=true を確認して再現。表示制御用のフラグを無料本文の除外条件から外し、実価格・限定公開の条件と有料境界の検査を維持した。

要約が利用できない場合は同じクリエイターの別の記事を自動で確認する。追加確認は最大3ページ・12記事で打ち切り、利用できる記事がなければその人を飛ばして続行する。スキ履歴では次の候補から補充し、候補全体が足りない場合も取得できた人数で完了する。タグ・マガジンの指定があれば、別の記事もその条件を確認する。1記事だけの初投稿条件、人物・記事の不一致に対する既存の保留は維持する。

切り替えた記事のサムネイル・タイトル・無料本文・URL・取得元の照合記録をまとめて更新してから画像を作成する。名前だけ・プロフィールを選択している場合や、要約が最初の記事から取得できる場合には、この追加の取得処理を行わない。最後の実績の算数は既定のURLを維持し、無料本文が不明な場合は名前表示にする。

旧版で保存された未取得の要約は、未貼付分の再開時、または「最初から」の再作成前に再取得する。貼り付け済みの画像は更新操作だけでは書き換わらず、既存の再作成操作で差し替える。

変更範囲：極薄単独配布2本、本文抽出、専用ビルドアダプター、更新導線、検証とCI。INSIGHT本体・通知・履歴API・DB・購入紹介の生成元は変更しない。

検証：新規19件成功（APIフラグ、価格・限定公開、有料境界、通常／履歴と極薄／中型の実PNG生成、別記事の画像・本文・リンク対応、記事なしのスキップと補充、全候補が未取得の場合の完了、タグ条件、途中再開、旧取得情報の再作成）。関連検査は136件成功、29件は旧版の記録がないためスキップ。日付・履歴の検査はUIと編集経路7件を実行し、未変更のサーバー処理3件は対象外とした。再構築と配布2本の構文確認成功。

公開APIの実データで ioRe 記事の無料本文、実績の算数の有料境界より前の本文をそれぞれ取得できることを確認。実ブラウザーの起動はUnix socketのEPERMで実施できず、実際のスマートフォン・ログイン済みnote画面への貼り付けは未検証。ProseMirrorとcanvasの実装を使う匿名fixtureで貼り付け・リンク・再開・保存を検証した。
