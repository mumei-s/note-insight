# 極薄サムネイル 2.9.5：手直し後の再開と連続貼付

基準：配布版2.9.4。作業前mainコミット `1d7c6e3a847bff77baa9f622b1be1dc841ef8494`。同じリポジトリのBOOST/INSIGHTなどは変更していない。

## 原因と変更

- 2.9.4は所有記録のある区切り線を利用者が削除・移動すると停止していた。このレイアウト補助と品質表示ボタン、明示修復APIの配布組み込みを外した。手動編集した文章や区切り線を復元しない。
- 区切り線は新規画像の後ろへ従来どおりnoteのネイティブ要素として挿入する。所有証明は今回分削除で手動要素を消さないために残す。区切り線の不確実性だけで画像処理を止めない。
- 完了位置は保存済みitemsの連続した先頭部分で判断する。完成した画像を手で削除しても、その画像を再送しない。別記事、重複した実画像ID、明確な投稿者/記事/生成ファイルの不一致、未確定アップロードは引き続き保護する。
- 通常の#・マガジンなどで開始されていなかったScreen Wake Lockを全画像経路と通知カード経路で開始する。作業中の解除・画面復帰時に再取得し、終了・停止後には解放する。
- 次の一人分のアイコンと記事画像だけを先読みする。noteへの画像送信は常に一件ずつ。先読み失敗は通常取得へ戻り、他人の素材と混ぜない。
- native画像到着はDOM変更で即確認し、補助ポーリングは500msとした。従来の40msごとの本文全走査を減らす。画面が非表示だった時間はアップロード待ち期限から除外する。未確定の画像を自動再送しない。
- 画像と区切り線の完了記録を一回にまとめる。毎回の描画文字測定・本文表示監視を通常経路から外す。元の画像、本文、リンク、件数、並び順、デザインは維持する。

## 検証

コード確認と匿名化した模擬note環境で実施。実際のProseMirror文書、Canvas PNG、配布スクリプトを使用。本番記事への貼付・削除・公開はしていない。

- continuous-v295 / dividers-v293 / source-scope-v293 / speed-v292 / quality-holds-v291：93件成功、失敗0、スキップ0。
- 配布同一性、パネル、保存、ストレージ、通知カード削除を含む別の対象セット：75件成功、失敗0、スキップ0（新規連続処理テスト14件との重複あり）。
- 新規の通常200人テスト：201画像と201本の区切り線、順序一致、最後の実績記事まで完了、自動一時停止なし。
- 削除/移動/変更された区切り線、削除されたプロフィール・完成画像からの再開、画面ロック解除・復帰、先読みと送信の重なり、バックグラウンド待ち、native失敗、意図的な別人混入を確認。
- 旧「編集された区切り線で停止/修復」のテストは、今回の利用者指定に合わせ「編集を保持して続行/再送しない」へ変更。独立した旧修復モジュールは配布しない。

速度：同じ端末代替環境・入力12人＋実績1件・空キャッシュ、素材取得30ms、native応答60ms、各3回。2.9.4中央値1705ms → 2.9.5中央値1101ms、35.4%短縮。貼付部分1684ms → 1074ms。取得通信数26件で同じ。全PNGと文書JSONが変更前と一致。抽出は13.66ms → 14.47msで短い処理の計測揺れがあり、抽出の高速化を達成したとは扱わない。これは模擬条件の結果であり、実際のスマートフォンの速度ではない。

## 未確認と戻し方

スマートフォン実機・実際のnoteサーバーとの通信は未確認。OS/ブラウザーがWake Lockを拒否する場合やアプリ切替中の画面点灯を保証できない。通常の前面表示で利用できる標準APIを用いる。note側のアップロード完了待ちと保存成功確認は省略していない。
