# 極薄＋通知 v18.8.7 再開修正

## 実機報告
v18.8.6で「送」が進まず、最終表示が「停止要求を受け付けました」になる。画像には末尾の実績の算数が見えるが、実機の画像総数・停止例外はスクリーンショットからは確定できない。既存原稿・画像と310件の対象一覧を保持する。

## 確認した不具合
- link-guardの例外表示は表パネルだけ更新していた。safety.stopが裏パネルへ書いた汎用停止文をsource-pickerの同期処理が表へ戻しており、具体的な理由が消えていた。
- 保存監視は記事キーを含む保存URLしか認めていなかった。noteの配信エディターはGET /api/v3/notes/{key}?draft=trueで数値IDを読み、POST /api/v1/text_notes/draft_save?id={id}へ本文・タイトルを保存する。
- 編集画面の再表示で画像IDが変わる場合、再開・送信前チェックにはsrcと記事リンクによる再照合がなかった。初期化だけに存在していた処理を、保持・再開する経路にも適用した。

## 修正
- 両方の状態表示へ同じ例外を書き、送信前チェックの例外を端末内に記録する。
- 現在の記事キーと一致する正規API応答から数値IDを取得し、保存先ID・現在の本文・タイトル・成功応答を照合する。他記事・古い本文・業務エラーを成功にしない。
- 取得済みの下書き本文とタイトルが現在の内容に完全一致すれば、保存済みとして扱う。
- 保存ボタンが見えない場合はnoteのAndroid向けregisterNoteDraft、またはエディターが登録するCtrl+Sの正規保存処理を使う。操作開始だけでは成功とせず、対応する保存応答を必要とする。
- 画像IDがない場合は保存済みsrcと記事リンクの一致する画像を特定する。候補が複数なら処理を進めない。

## 検証範囲
テストでは保存API/XHR、正規保存中の文書正規化、下書きの再表示、画像IDが変わった310件の通知カード作成、曖昧な画像の拒否、状態表示の上書き防止を確認する。公開後のAndroid実機で310件の通知カードが完成することは、まだ確認できていない。
