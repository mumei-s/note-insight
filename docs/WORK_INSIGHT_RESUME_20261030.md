# 「INSIGHTで問題点抽出」再開・追加修正 2026-10-30

開始時のmainは `a913ab671128273c092f32d3bac3dddde5996af0`。
通知の軽量化・保存済み画面の差分更新・関係履歴の既存修正を維持して、次の再現できた問題だけを修正した。

## 通知を開いたままスマホで別アプリへ移った後の更新停止

Readerはvisibility hiddenで内部のstopを立て、同一パネルへ戻った後も停止を保持していた。
ブラウザによる一時中断と利用者による一時停止を分離し、visible/focus/pageshowの重複時も差分確認を一度だけ再開する。
明示した一時停止・機能OFF・バックグラウンド中の取得停止は維持する。
初回全履歴・保存済み境界・次の新着・パネル再表示・中断中の応答競合を回帰テストで確認する。

## 自動フォロワー確認中のnoteアカウント切替

自動確認は開始時だけnoteログインを確認していたため、プロフィール取得の途中で別アカウントへ切替えると、その関係フラグを元の本人として保存できた。
各プロフィールの取得後、保存前にnoteログイン・連携token・reader種別を再確認する。
非表示・明示照合の開始も保存前に検知し、停止時は続き位置を進めない。
12人・6時間の既存取得上限とowner限定動作は維持する。

## 連携画面の最新版判定

localStorageの版番号だけでは起動を証明できない。
現在のdocumentへuserscriptが公開したlive版だけで最新版判定し、保存版だけが最新でも未確認表示と更新入口を保持する。
live版の到着・削除を監視し、連携APIや履歴を再取得しない。

## 更新が文字列または途中ページで止まる場合

Tampermonkeyの `script_installation.php` へ直接進む処理を撤廃。
クエリなしの正規 `.user.js` を拡張機能に渡し、拡張機能自身が導入方式を選べるようにする。
捕捉しない端末では同じ画面に「更新用URLをコピー → TampermonkeyのURLからインポート → 更新確定」を表示する。
コピーやクリックだけでは更新済みとしない。実際の新版起動・元アカウント・戻り先を確認する。
ブラウザに未導入/無効な拡張機能をWebページから有効にしたり、実機更新済みと偽装する処理は追加しない。
