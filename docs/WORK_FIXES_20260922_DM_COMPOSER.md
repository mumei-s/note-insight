# DM入力欄と読み込みパネルの重なり

## 最新の依頼

2026-09-22、更新パネル・通知Storage対策の公開確認中に、ユーザーから「dm欄のパネルが邪魔でメッセージうてない」と追加報告。画像1000015189.jpgでは画面下の固定パネルがnoteのメッセージ入力欄を覆っていた。本文40・保存20の表示もあるが、全件保存の実機検証完了とは扱わない。

公開済みmain `e5deb8801ba48881b1764f973be121c2e8a19ff6` を起点としてDMだけを分離修正。前回の更新パネル・通知保存対策は維持する。

## 変更内容

- DM会話画面では、見えている入力欄と周辺の送信コントロールの位置を測定し、その上に8px空けてパネルを置く。固定bottom値だけで置かない。
- 入力欄を見つけられない、または表示スペースが足りない時はパネルを隠す。入力欄がどこか分からないまま下部を覆わない。
- パネルは上下4px、操作ボタンは高さ32pxの薄型表示。本文・保存・相手の進捗を維持する。
- textarea、contenteditable、plaintext-only、role=textboxの入力中は即時非表示。遅れて届いた保存進捗で再表示させない。
- VisualViewportでソフトキーボード・拡大表示を検出し、表示位置を更新する。非対応ブラウザでも入力フォーカスと通常のresizeで保護する。
- 入力欄の伸縮、画面回転、viewportのresize/scroll、DOM変更に追随する。
- 入力が終わると安全な位置へ戻す。パネルの非表示は手動停止扱いにしない。
- 本人が文字入力中は、その会話の自動履歴スクロールを止める。取得済みの本文は保存し、全件取得済みと誤判定せず途中状態にする。フォーカスが外れたら再開する。別の非表示ルームの取得は継続できる。
- 下書き・キャレット・入力値を変更しない。入力欄とその子要素を送信済みDM本文として収集しない。
- DM一覧では進捗と操作ボタンを維持する。🔔表示時・他画面では従来どおりDMパネルを除去し、遅い応答で復活させない。
